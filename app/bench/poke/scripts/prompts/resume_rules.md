EVIDENCE RULE: your latest tool results outrank your memory files. MEMORY.md and maps/*.md are notes about older observations, and a dream can harden a misread coordinate into SEALED or NOT FOUND. If the last ~100 actions produced no new map, no new item and no progress, treat the nearby SEALED / NOT FOUND / dead-end claims as unverified: pick the strongest one, re-test it with a bounded run (up to ~100 actions), write down the result, and only then move to the next lead. Do not repeat a loop just because a note says the exit does not exist. LOOP RULE: if the last ~50 actions show a loop - the same map or tile revisited 3+ times, the same warp pair crossed back and forth, or the same edge/probe repeated with no new tile, item or map - stop following the current TODO and diagnose the cause in one line. Read the action log back to the first occurrence of the pattern, not just the last few actions, and name the assumption that keeps it alive: a wrong SEALED/wall claim, a probe form that cannot log 'blocked', a probe on the wrong floor, an unexplored ladder or region, or a TODO that repeats itself. Then choose a structurally different lead: an unvisited tile or ladder, a different floor, or a different probe form. If the cause is a contradicted memory claim, write a memory_note and call memory_dream with reason 'loop: <cause>' instead of spending another 50 actions on the same edge. Never repeat a probe or a TODO item just because it is written down. A loop is a wrong assumption repeating, not bad luck; compare the tiles you have visited with the ones you have never visited, and treat an unvisited ladder or region as a stronger lead than a known wall. DREAM RULE: __DREAM_RULE__. A soft due is advisory: you may finish the current battle or a short route first, but do not let it drift. poke_act and poke_program refuse only at the hard cap or when notes, memory writes, a new map or new SIGHT cross their trigger. Battle turns never block: the dream waits until the battle ends. A low-information soft window (no new note, no map change, no new SIGHT) may be deferred once automatically; the next window is not skippable. Dream immediately after a blackout or a lost rival/gym battle: money and position changed, and the next plan depends on it. When a dream runs, call memory_dream: the dream runs in a separate agent that has no game tools, reads your action log and notes/ mailbox, and rewrites MEMORY.md and the map files in its own context. You do not review or rewrite memory during a dream. Wait for it, then call read MEMORY.md and check the rewritten notes before the next game action. You may also start a voluntary dream at any time when you notice a contradiction, a repeated loop, a major new area, a stale note, or a dream question you have answered; voluntary dreams also run in the separate agent, do not consume game actions, and reset the action and write counters. PLAN RULE: use `plan` when the TODO queue is only short tactical moves, when the same loop repeats, after a blackout or a lost rival/gym battle, or when a lever is exhausted. It writes a `## PLAN` block into TODO.md with one measurable goal and 3-6 strategic milestones, and it does not consume a game action; calling it is a deliberate pause in the action loop. The PLAN block is shown after every action. Replace it with `plan` when the evidence changes; never keep executing a plan that a note or a battle has already refuted. The dream preserves the PLAN block and only rewrites the tactical checklist below it. NOTES RULE: you have memory_note. Use it for information the dream cannot recover from the action log: a new inference from SIGHT (for example a wall row), a contradiction with MEMORY.md, a question for the dream, or a verified answer to a TODO question. Write one short note per claim, naming the map and tile or direction and the evidence. The dream reads notes/ at the start and deletes each note after folding it into MEMORY.md, maps, or TODO.md. Do not use write or edit on notes/ and do not delete notes yourself. Notes are a delta since the last dream, not a replacement for MEMORY.md or TODO.md. BIDIRECTIONAL RULE: when TODO.md contains a question from the dream, verify it in the game, answer it in TODO.md or a memory_note, then call memory_dream with a one-line reason such as 'answer to TODO question' so the dream can consume the answer. A voluntary dream does not consume game actions and resets the action counter.
